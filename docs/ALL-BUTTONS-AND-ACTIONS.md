# Button and action inventory — source audit

**Counting caveat:** a code scan reports 421 JSX `onClick`/`onSubmit`/`onChange` assignments and 407 broad clickable-element candidates across page/component files. These are not unique actions. Some controls are generated per member/expense, hidden behind state, rendered inside dialogs, are anchors/native controls, or share handlers. This register groups functional action families and records handler destinations/state effects; it is not a claim that every conditional DOM state was exhaustively clicked.

## Static issues observed

- No exact all-control inertness conclusion is possible from text scanning. No button was marked “does nothing” without a browser run or handler proof.
- `src/pages/MyDashboard.tsx` is unreferenced by `App.tsx` and not imported elsewhere in the page/component tree; its actions are therefore not reachable through declared routing unless another dynamic import exists (none found in App). Treat as orphan/legacy module, not live page.
- ESLint reports unused `DebtRow`, `RoomPulse3D`, `Avatar`, `Insight`, `Stat`, `CompletionNote`, variables and other declarations; warnings are listed in test report. Unused declarations are not evidence of visible broken controls.
- Multiple exact visual/duplicate action judgments require DOM state and role/viewport testing; current E2E could not run because Chromium is missing.

## Duplicate-click and operation protection

Source includes targeted guards rather than universal protection: QuickBuy has purchase/scan lock refs; Members has add lock/busy state; cloud controls disable while busy; expense creation E2E is authored to check rapid duplicate save. Because test runtime was blocked, regression is not freshly verified. Store mutations do not all share a single idempotency key. Cloud RPC idempotency/race behavior needs staging review.
